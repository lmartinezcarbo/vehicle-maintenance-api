# DISEÑO DE BASE DE DATOS

El modelo conceptual que estamos construyendo es:

USER
│
└── VEHICLE
│
└── MAINTENANCE_RECORD
│
├── MAINTENANCE_PART
│        │
│        └── PART
│
└── EXPENSE

## Users

Campos previstos:

* id
* name
* email
* password_hash
* created_at

## Vehicles

Campos previstos:

* id
* user_id
* make
* model
* year
* vin
* mileage
* created_at

Relación:

User 1 → N Vehicles

## Maintenance Records

Campos previstos:

* id
* vehicle_id
* service_type
* description
* mileage
* service_date
* labor_cost
* notes
* created_at

Relación:

Vehicle 1 → N MaintenanceRecords

## Parts

Campos previstos:

* id
* name
* manufacturer
* part_number
* description

## Maintenance Parts

Tabla intermedia para relación muchos-a-muchos.

Campos previstos:

* id
* maintenance_record_id
* part_id
* quantity
* unit_cost

Relación:

MaintenanceRecord N → N Part

## Expenses

Campos previstos:

* id
* vehicle_id
* maintenance_record_id
* category
* amount
* description
* expense_date

`maintenance_record_id` puede ser nullable si queremos permitir gastos que no estén asociados directamente a un mantenimiento.
